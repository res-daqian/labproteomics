# 如果是我来讲：lab meeting 的讲法（给 Daqian 的讲稿提纲，2026-11-06）

总时长 12 到 15 分钟，其中现场操作约 8 分钟。原则：先讲问题，再讲工具；每一页只强调一个判断；数字只说和论文一致的那几个；结尾要东西（注释表、pooled QC、marker 名单）。

## 开场 60 秒：从一个问题讲起
- 「我们每个人拿到 DIA-NN 的结果之后，做的事情其实是一样的：看看 run 好不好，归一化，比较两组，做富集，然后写下来。问题是这些步骤现在散在脚本里，只有写脚本的人能跑，而且每个人的阈值不一样。」
- 「导师让我把 PhD 的分析链打包成一个本机运行的应用。今天给大家看的是能跑通的第一版，不是成品。我用自己的 Long-term 数据演示，因为我最清楚它该长什么样。」
- 一句话定位：**它不是一个新的统计方法，而是把同一套方法、同一套 QC、同一套记录交给每个人。**

## 三个设计原则 60 秒（放一张幻灯片或口头说）
1. **QC 在统计之前**：设计、单个 run、整个队列三层；排除决定在看任何比较之前做，并且写进记录。
2. **每个选择都可见**：阈值都是界面上的参数，记录里逐项列出；默认值是论文锁定的设置，可改。
3. **每个 hit 都被描述而不只是被计数**：判据原文、每个 run 的值、留一法稳定性、检出差异另列。

## 现场操作 8 分钟：每页只强调一件事
- 页面 1：**设计检查先于统计**。指着红色那条说：四个跨批次对比 confounded，这就是论文里 LIM vs CNT 只能当 supportive 的原因，工具在算任何统计之前就说出来了。
- 页面 2：**三层 QC 给出同一个结论**。成绩单两项以上标记的 CNTA_L_4L 和 LIMA_L_89L，与论文一致；marker 面板说明解剖干净；队列层候选离群也在这几只。然后当场排除 L_CTRL_4 和 L_CTRL_BLK 的四个 run，强调「证据在先，决定在先，记录在后」。顺带一句：QC 报告可以一键导出 PDF，指标还按 HUPO-PSI 的 mzQC 标准另存一份。
- 页面 3：**结果和论文一样，但多了三样描述**。Summary 里 1985、47、303 与论文一致；fragile 列是留一法；空心点就是它；detection-only 单独列。点一个蛋白看配对连线。
- 页面 4：**Rescue 的定义印在旁边**。Tier 1 = 15、Tier 2 = 180；drug-only 只标注不过滤；11 个 Tier 1 在某个对比里 fragile，这是证据等级的标注，不是撤回。
- 页面 5：**ORA 的背景是本对比定量到的蛋白**，不是整个基因组；GSEA 用模型 t 统计量排序。
- 页面 6：**一个文件夹就是一次分析**：输入 MD5、参数、版本、表、图、报告、上传表。打开 HTML 报告滚一遍即可。

## 边界 60 秒（主动说，比被问到好）
- DIA-NN 输入用两套真实数据验证过；Spectronaut、FragPipe 接了但没数据测。
- 留一法只重拟合模型，不重做归一化；检出差异的 Fisher 检验忽略配对，是线索不是结论。
- 计算是同步的，QC 和每个对比各约半分钟。
- 还没有表型关联、第二个统计引擎、Windows 实机测试。

## 结尾 60 秒：要三样东西
1. **注释表**：每个 run 的组、动物或供体、批次、上样顺序。模板里 run 名已经填好。
2. **以后实验带 pooled QC**：它是技术精度和漂移唯一的直接量度。
3. **各组织的 marker 名单**：RPE/脉络膜、巩膜、泪液的名单现在只是起点。
最后一句：「给大家的版本里带的是公开数据集，安装步骤在 README 里；谁愿意用自己的数据先试，我来陪跑。」

## 可能被问到的问题与回答
- 为什么默认 p 不是 q：n = 10 配对时 q 过严；两列都在，一键切换。
- 配对怎么处理：subject_id 进模型作区组因子，只用两组都有的动物。
- fragile 是不是假阳性：不是判定假阳性，是证据等级；n 小时依赖单只动物很常见。
- 数据会不会上传：不会，本机 R 进程，浏览器只是界面。
- 能不能用 Spectronaut：导入已接入，需要一个真实文件来测，欢迎提供。
- 什么时候能装：README 的三步；先在一两台机器上试装，再推广。
