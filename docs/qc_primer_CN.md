# 蛋白组学 QC 入门：每个指标为什么要看（给 Daqian 的讲义，2026-11-05）

写在前面。QC 只有一个目的：在做生物学解释之前，把「技术变异」和「生物变异」分开，并确认每个数字是可信的。
所以每一个 QC 指标都对应一种具体的「故障模式」（failure mode）：它测什么、什么故障会让它变、变了会怎样污染下游结果、看到了怎么办。
下面按三层讲：实验设计层（数据进来之前）、单个 run 层（仪器与鉴定）、队列层（归一化之后）。
平台页面 1 和页面 2 已经按这三层实现。

## 0. 一个总的思路：方差从哪里来

一个蛋白在两组之间的差异 = 真实生物差异 + 解剖/取材差异 + 样品前处理差异 + 仪器差异 + 搜库/定量误差。
统计检验只能回答「观察到的差异是否大于组内波动」，它分不清这些来源。QC 的工作就是逐层把后四项量化、尽量压小，
压不掉的至少要知道它们和分组是否纠缠（confounding）。纠缠了的部分，统计学上无法补救。

## 1. 设计层：数据进来之前

**1.1 上样顺序随机化 / 区组化（run order）**
- 测什么：各组的样品在仪器序列中的位置。
- 为什么：仪器性能在一个序列里会漂移（喷雾稳定性、柱子老化、泵压、质量校准）。强度、鉴定数会随时间单调变化。
  如果 A 组先跑、B 组后跑，漂移就会变成一个「组间差异」，而且方向一致、几乎每个蛋白都有，统计上非常「显著」。
- 看到了怎么办：事前把各组交替排列（配对样品相邻），事后只能靠漂移图识别并如实声明。
- 平台：页面 1 设计检查做 Kruskal-Wallis 检验看各组 run order 是否分布不同；页面 2 漂移图。

**1.2 批次记录（batch）**
- 测什么：消化批次、日期、操作者、试剂批号。
- 为什么：不同批次的消化效率（漏切率）、氧化、脱酰胺、上样量都会系统性不同。批次与组别重合时，差异分析得到的是「组别 + 批次」的混合效应。
  你 Part II 的 LIM vs CNT 就是这样：两个消化批次恰好各自对应一种 lens 状态，所以论文里只能作为 supportive。
- 平台做的检查：batch × group 列联表；每一对组别判定为 confounded（无共同批次）、crossed（有共同批次，可作为协变量）或 same single batch（同一批次内）。
  对 demo 数据，CNT_L / CNTA_L 都在 Date_0721，LIM_L / LIMA_L 都在 Date_0828 → 四个跨批次对比全部 confounded；两个配对对比在批次内。
- 一个新的证据（页面 2 成绩单「系统差异」表）：两个批次在平均肽段长度（12.1 vs 12.5）、平均电荷（2.40 vs 2.48）、保留时间偏差、峰宽上都有显著差异（p 在 1e-6 量级）。
  这是消化和色谱条件在批次间不同的直接证据，比任何推测都硬。

**1.3 Pooled QC 与系统适用性标准品**
- 做法：把所有样品各取一点混成 pool，每 8–10 个样品插一针；每批开头和结尾跑一个商业标准品（HeLa 消化物、iRT）。
- 为什么：pool 没有生物差异，它的任何变化都是技术变化。它给你四样东西：
  (a) 每个蛋白的技术 CV（精度底线：低于这个 CV 的 fold change 不可解读）；
  (b) 漂移的直接测量（pool 的强度/鉴定数随序列变化）；
  (c) 批次校正的锚点（QC-RLSC 等方法只能靠它）；
  (d) 仪器出问题时的早期报警（pool 鉴定数跌了，可以当场停机）。
  标准品回答另一个问题：仪器今天是不是在它平常的状态（与样品类型无关的基准）。
- 你们的现状：旧数据基本没有。没有 pool 时，平台用同一动物双眼的一致性（within-subject correlation）和漂移图代替，但这是弱替代：双眼之间有真实的生物差异。
- 建议：以后每个实验带 pool；标准品至少每批首尾各一针。平台会自动识别 group 或样品名里含 pool / QC / HeLa / standard / blank 的 run。

**1.4 元数据完整性**
- sample_id → 动物、眼别、组、批次、日期、顺序、上样量。缺一项，后面某一类故障就无法诊断。

## 2. 单个 run 层：仪器与鉴定质量（页面 2「Run scorecard」）

数据来自 DIA-NN 的 `report.stats.tsv`（每个 run 一行）。平台在批次内（每批 ≥ 4 个 run 时）用中位数 ± 3 MAD 标记，这样「单个坏 run」和「批次整体不同」分开报告。

| 指标 | 测什么 | 什么故障让它变 | 对结果的影响 |
|---|---|---|---|
| Precursors / Proteins identified | 鉴定数 | 上样少、喷雾差、喷针堵、色谱劣化；或样品本身被高丰度污染物压制（如晶状体） | 这个 run 缺失值多；缺失集中在低丰度端（MNAR），会偏移它所在组的 fold change |
| Total quantity / MS1 / MS2 signal | 总离子信号 | 上样量不同、喷雾不稳、离子源脏 | 归一化因子偏离 1；差太多时归一化也救不回线性范围 |
| FWHM (scans) | 一个色谱峰上有几个采样点 | 峰太窄或扫描太慢 | 点数少 → 峰面积噪声大 → 定量不准 |
| FWHM (RT, min) | 峰宽 | 柱子老化、死体积、漏液、梯度问题 | 峰宽 → 更多共流出 → DIA 窗口里干扰更多 |
| MS1 / MS2 mass error (ppm) | 质量校准偏差 | 校准漂移、温度 | 偏差大 → 窗口内匹配不到 → 鉴定数掉、定量错 |
| RT prediction accuracy | 观察 RT 与对齐后库 RT 的偏差 | 梯度变了、换柱子、离群 run | 对齐质量差 → 鉴定置信度下降 |
| Normalisation instability | 归一化因子在一个 run 内沿梯度的波动 | run 中途喷雾抖动 | 单一归一化因子修不平这个 run |
| Missed cleavages | 平均漏切 | 消化不完全（酶比、时间、变性不足） | 肽段分散到多种形式 → 灵敏度下降；批次间不同 → 某些蛋白出现系统性假差异 |
| Peptide length / charge | 肽段物理性质的平均 | 消化或电离条件变化 | 本身不是坏事，但批次间差异说明前处理不同（demo 数据正是如此） |

此外值得补的（DIA-NN stats 没有直接给，需要从 report 里算）：甲硫氨酸氧化、脱酰胺、氨甲酰化比例（样品处理的指纹），角蛋白与胰酶自切比例。

看到了怎么办：
- 单个 run 两项以上标记 → 看它的原始数据（TIC、喷雾），决定是否重跑或排除；
- 整批偏移 → 这是设计层问题，写进记录，作为协变量或限制结论。
- demo 数据的结果：批次内标记 CNTA_L_4L（总量、MS2 信号低）和 LIMA_L_89L（MS1 质量误差、漏切高）——这两只正是论文 QC 里的候选离群。

## 3. 样品层：组织纯度与污染（页面 2「marker panel」）

眼组织的最大非仪器方差来源是解剖：视网膜带上一点晶状体或 RPE，巩膜带上一点肌肉或脉络膜，泪液混入血液或皮肤。通用指标看不见这些，只能用标志蛋白。

- 做法：对每个 run，计算一组标志蛋白占总离子信号的比例（用导入时的原始强度，不归一化，因为要看的就是组成差异）。
- 面板（可编辑）：光感受器 / 神经视网膜（RHO、PDE6、RCVRN、SAG…）、RPE（RPE65、BEST1、PMEL、TYRP1、DCT…）、晶状体（CRY 家族、BFSP、MIP）、血细胞（HB、ALAS2、SLC4A1…）、血浆（ALB、FGA/B/G、APOA1、A2M…）、巩膜/脉络膜 ECM（COL1A1、DCN、LUM、KERA…）、平滑肌、骨骼肌、皮肤角蛋白（KRT1/2/9/10、DCD）、眼表上皮角蛋白（KRT3/12/5/14…）、泪液蛋白（LYZ、LTF、LCN1、PIP…）、Y 染色体蛋白（性别核对，人和小鼠可用）。
- 角色随组织变：视网膜样品里 RPE、晶状体是「邻近组织」，角蛋白是「污染」；泪液样品里泪液蛋白是「预期」，皮肤角蛋白是污染。预期集合在偏低时标记，其他集合在偏高时标记。
- 为什么重要：晶状体蛋白极丰富，一点点就能压低整个 run 的鉴定数并扭曲归一化；如果解剖质量恰好随组别不同（比如一个人解剖对照、另一个人解剖实验组），RPE 或 ECM 蛋白就会变成「差异蛋白」。
- demo 数据：12 个集合都有蛋白；光感受器约 4.3% 的总信号；晶状体 0.002%、RPE 0.008%、血红蛋白 0.07% —— 解剖很干净；只有 CNT_L_4R 的骨骼肌比例偏高（0.25%）。
- 每种组织的面板需要和你一起定（RPE/脉络膜、巩膜、泪液）；表里的名单是起点，不是定论。

## 4. 队列层：归一化之后（页面 2 其余图）

- 缺失值模式：看「部分缺失」的肽段的强度分布。缺失集中在低强度 → MNAR（低于检测限），这决定了不能用随机补值；缺失随机分布 → MCAR，可以更宽松。某个 run 缺失明显多 → 它是弱 run。
- 归一化前后分布：归一化假设「大多数蛋白不变」，只能平移位置。如果某个 run 的分布形状不同（不只是中位数），归一化修不了，要回到前几层找原因。
- PCA：按组、按批次、按顺序分别着色。PC1 跟批次走 → 批次效应；跟顺序走 → 漂移；一个点孤悬 → 离群；pool 应该聚在中心。demo 里 PC1（35%）同时是组别和批次，这就是混杂的图像。
- 相关矩阵与聚类：同组、同动物应更相近；某个 run 和谁都不像 → 离群；按日期聚 → 批次。
- 漂移图：中位强度或鉴定数对 run order。单调趋势 = 仪器劣化或残留累积。
- 双眼一致性：同一动物两眼的相关系数；配对设计里它是最接近「技术重复」的东西；明显低的一对要怀疑样品调换或一只眼解剖出了问题。
- MAD 离群筛查：缺失率、相关性、强度偏移三项分别在组内用中位数 ± 3 MAD 标记；两项以上才算候选。demo：CNTA_L_4L、LIM_L_1R、LIM_L_3L。
- Pooled QC 的 CV（有 pool 时）：蛋白水平中位 CV < 10–15% 是常见目标；没有 pool 时用双眼一致性代替，但要明说。

## 5. 判据先于结果

- 排除规则在看差异分析之前定好并写下来：例如鉴定数低于批次中位数 70%、成绩单两项以上标记、marker 面板显示污染、队列层两项以上标记。
- 绝不能因为某个 run「让结果不好看」而排除；平台把排除的 run 和理由写进运行记录。
- 批次不混杂时作为协变量进模型；混杂时如实标注为 supportive。
- 页面 3 的留一法（leave-one-out）是 QC 的延伸：一个 hit 如果去掉某一只动物就不显著，它依赖单个样品。demo 里 LIMA_L vs LIM_L 的 47 个 hit 中 28 个是这种「脆弱」hit；15 个 Tier 1 里 11 个在两个对比之一是脆弱的。这不是说它们是假的，而是说 n = 10 时它们的证据等级要写清楚。

## 6. 社区与业界做法（供参考）

- 每 8–10 针一个 pooled QC、每批首尾标准品，用控制图（Levey-Jennings / Shewhart）跟踪鉴定数、信号、质量误差、峰宽，设定事前验收标准。
- 工具：DIA-NN / Spectronaut 自带的 per-run 统计；PTXQC（MaxQuant/FragPipe 生态）；RawBeans；Skyline + AutoQC / Panorama（系统适用性）；MSstatsQC（控制图）；MS-DAP 的 QC PDF。
- 标准格式：HUPO-PSI 的 mzQC（2024 年 1.0），R 包 MsQuality 可算 43 个底层指标；DIA 专用判据目前仍靠各软件自己的报告。
- 富集分析里最常见的错误与 QC 同源：背景集。ORA 的背景必须是本次定量到的蛋白，不是整个基因组（Wijesooriya 等 2022 发现 95% 的发表分析没有正确设置或声明背景）。平台页面 5 的 ORA 固定用本对比定量到的蛋白作背景。
